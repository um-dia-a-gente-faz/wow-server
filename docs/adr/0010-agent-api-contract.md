# ADR 0010: Versioned, schema-checked agent API contract

## Status

Accepted (#264).

## Context

`agent/http_api.py` is consumed by `tools/wowmap` and `tools/agent-runner`. The shapes
were implicit and each side had hand-written fixtures, so a field rename passed both test
suites and broke the console live (the class of bug in #132). The agent host and the VM
deploy independently (ADR 0002), so old and new versions meet in production routinely.

`agent/` and `tools/wowmap` ship in different Docker images (`Dockerfile` copies `agent/`;
`wowmap/Dockerfile` has `tools/` as its build context and cannot see `agent/`). The agent
runner runs from the repo checkout on the agent host. No new pip dependency is allowed.

## Decision

- One plain JSON file, `agent/api_schema.json`, describes every response in a small
  JSON-Schema subset (`type`, `properties`, `required`, `items`, `enum`). Unknown fields are
  always allowed. `agent/api_contract.py` holds a ~40 line stdlib validator, a fixture
  generator (`sample()`) and the Markdown renderer.
- Every JSON response from the agent carries an integer `api_version` (added in
  `_send_json`, so success, error and `/control/walk` bodies all get it). Existing fields and
  routes are unchanged. SSE messages are not versioned.
- Only the integer travels at runtime: `API_VERSION` in `http_api.py`, `SUPPORTED_API_VERSIONS`
  in wowmap and in the runner. The schema file is not copied into the wowmap image. Tests
  pin each constant to the schema's `api_version`, and CI runs from the repo where all of
  them exist, so a shape or version change in one place fails the other suites in the same PR.
- Producer tests validate real server responses; consumer tests build their fake agents from
  `sample()`, so renaming or retyping a schema field breaks them.
- Consumers: an absent `api_version` is an older agent and is treated as version 1 (the shape
  is the same). A present but unsupported version gives wowmap a 502 with `code: api_version`
  and the message "agent API version X not supported", which the Agent mind tab shows instead
  of an empty tab; the runner reports `agent_api.state = "unsupported"`.
- `docs/AGENT-API.md` is generated by `python3 -m agent.api_contract > docs/AGENT-API.md`;
  a unit test fails when it is stale.

## Consequences

- Additive changes (new field) keep `api_version`; add it to the schema and regenerate the doc.
  A breaking change bumps `api_version` in the schema, `http_api.py` and, once the consumer
  can render it, adds the new version to the consumers' supported tuples. Consumers ship
  first, producers second, so skew degrades to the "not supported" message, not to garbage.
- The schema is hand-written, so a producer field that nobody put in the schema is not
  caught; only the declared fields are checked.
- Consumer tests import `agent.api_contract` from the repo root (they run from a checkout in
  CI), which the wowmap image never needs.
