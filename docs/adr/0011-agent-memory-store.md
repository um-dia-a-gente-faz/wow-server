# ADR 0011: Durable agent memory store

## Status

Accepted (#276), module only. No consumer is wired in and no compose or `scripts/` change
is made in this decision. The volume and the first consumers follow in separate issues
once the owner has read this ADR.

## Context

Everything the agent knows lives in process memory: `GameState`, `WorldState`,
`ThinkState`, `known_targets` and the handle map. The only file the agent writes is the
audit JSONL, which is log output and is never read back as state. A container restart, a
crash, or a reconnect that creates a new session loses known NPCs, vendors and mailboxes,
recently failed targets, the action history used to demote candidates, and the current
goal. An unattended run that restarts mid-way starts blind (#98).

## Decision

- `agent/memory.py` is a small `sqlite3` store, one file per agent. The path is given by
  the caller; the intended location is `AGENT_STATE_DIR/<agent>/memory.db`, which is not
  wired in yet. Stdlib only, and the module imports nothing else from `agent/`.
- Interface: `Memory(path | None, now=time.time)`, `remember(kind, key, value, ttl=None)`,
  `recall(kind, key)`, `recent(kind, n)` (newest write first), `flush()`, `close()`.
  `value` is stored as JSON. `ttl` is in seconds; `None` never expires.
- Writes go through one writer thread (daemon) and a queue, so `remember` returns without
  touching the disk. Reads use a second connection; in the in-memory store there is one
  connection, shared by the readers and the writer behind one lock. `flush()` waits for the
  queue, and `close()` drains it, stops the writer and closes the connections.
  Once `close()` begins, `recall` and `recent` return nothing without taking the lock, including
  a call that was already waiting for it (#691).
- Schema version is `PRAGMA user_version`. Migrations are forward-only: a list of SQL
  strings in `MIGRATIONS`, each applied in its own transaction, with the version bumped in
  the same transaction. Never edit a migration that has shipped; append one.
- Advisory only. A recalled value is a hint and must be checked against live perception
  before the agent acts on it. Memory is never the source of truth for position, HP or
  targets that are in view.
- Degradation, never a crash. A missing directory is created. A corrupt file, a file that
  cannot be opened, or a file whose `user_version` is newer than this code knows gives an
  empty in-memory store, with one warning. The bad file is left untouched, so a newer
  build or a human can still read it. No public method raises; a value that is not
  JSON-serialisable is dropped with a warning.

## Data model

One table, `memory`:

| column | meaning |
|---|---|
| `kind` | what the entry is (`known_target`, `failed_target`, `goal`, ...) |
| `key` | identity within the kind (an NPC name, a goal id) |
| `value` | JSON text |
| `expires_at` | epoch seconds, or NULL for no expiry |

Primary key `(kind, key)`. A write replaces the row, so `recent` order is write order
(`ORDER BY rowid DESC`): rewriting a key makes it the newest.

## Ownership of `kind`

Each `kind` has one owning module that is the only writer. Readers may be any module.
Initial assignments, none of which writes yet:

| kind | owner | what it holds |
|---|---|---|
| `known_target` | `agent/known_targets.py` | NPCs, vendors and mailboxes seen before |
| `failed_target` | `agent/think.py` | targets that recently failed, used to demote candidates |
| `goal` | `agent/think.py` | the current goal and persona progress |

A new kind is added here in the same PR that first writes it. Two modules writing one
kind is a design change, not a drive-by edit.

## Consequences

- `remember` is asynchronous. A reader in the same process sees a write only after
  `flush()`, or after the writer has run; code that needs read-your-write calls `flush()`.
- Writes are committed one at a time. This is simple and cheap at the volume a think
  loop produces; batching is the upgrade path if the writer ever falls behind.
- A corrupt file silently costs the agent its memory for that run (one warning in the
  log). That is accepted: losing memory is recoverable, crashing the agent is not.
- Each agent gets its own file, so there is no cross-agent locking.

2. Does `goal` move to a future goal module, or stay owned by `think.py`?
